# Tic-Tac-Toe API

Веб-сервис для игры в крестики-нолики против компьютера. Компьютер выбирает ходы с помощью алгоритма Минимакс, поэтому проиграть ему нельзя: в лучшем случае получится ничья.

Учебный проект на Python. Цель: потренировать многослойную архитектуру, внедрение зависимостей и работу с базой данных на небольшом, но законченном приложении.

## Возможности

- Игра с компьютером через REST API
- Алгоритм Минимакс для выбора хода (с учётом глубины: компьютер предпочитает быстрые победы)
- Валидация поля: нельзя изменить уже сделанные ходы, нельзя сделать больше одного хода, нельзя пойти не тем символом
- Определение конца игры (победа, ничья) и победителя
- Несколько игр одновременно, у каждой свой UUID
- Игры хранятся в PostgreSQL и переживают перезапуск сервера
- Две веб-страницы: создание игры и игровое поле

## Стек

Python 3 · Flask · SQLAlchemy 2.0 · PostgreSQL · psycopg · python-dotenv · Werkzeug · Docker Compose

## Архитектура

Приложение разделено на четыре слоя, у каждого своя ответственность:

```
src/
├── web/          # маршруты Flask, модели запросов/ответов, мапперы, шаблоны и статика
├── domain/       # модели, исключения и интерфейс сервиса
├── datasource/   # подключение к БД, ORM-модели, репозитории, мапперы, реализация сервиса с Минимаксом
├── di/           # контейнер зависимостей
└── main.py       # точка входа
```

- **domain** ничего не знает о Flask и способе хранения данных.
- **datasource** хранит данные в PostgreSQL через SQLAlchemy. Репозиторий получает фабрику сессий, открывает сессию на каждый вызов метода и конвертирует модели через мапперы.
- **web** преобразует данные между форматом клиента (JSON) и внутренними моделями. На границе web строка превращается в UUID и обратно.
- **di** (класс `Container`) собирает граф зависимостей: фабрика сессий, репозиторий и сервис.

### Работа с базой данных

- Подключение описано в `datasource/database.py`: engine, фабрика сессий `SessionLocal` и базовый класс `Base`. Параметры читаются из `.env`.
- ORM-модели используют аннотации SQLAlchemy 2.0 (`Mapped[...]`, `mapped_column(...)`).
- Таблица `games`: `id` (UUID, первичный ключ) и `board` (двумерный `ARRAY` целых чисел).
- Таблица `users`: `id` (UUID, первичный ключ), `login` (уникальный), `password_hash`.
- Domain-модели отделены от ORM-моделей. Мапперы копируют поле (`deepcopy`), чтобы изменение в одном слое не влияло на другой.
- Сохранение игры через `Session.merge`: один метод работает и для новой игры, и для следующих ходов.
- Если игры нет, репозиторий возвращает `None`, а сервис и контроллер превращают это в `GameNotFoundError` и ответ 404.
- Таблицы создаются при старте приложения (`Base.metadata.create_all`). Модели импортируются в `main.py` ради регистрации в `Base.metadata`.
- Пароли хранятся только в виде хеша (`werkzeug.security`, scrypt с солью).

## Как запустить

```bash
git clone https://github.com/nikolyyya/tic-tac-toe
cd tic-tac-toe
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install flask sqlalchemy "psycopg[binary]" python-dotenv
```

Создай файл `.env` в корне проекта (шаблон лежит в `.env.example`):

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASS=postgres
DB_NAME=sa
```

Запусти PostgreSQL и приложение:

```bash
docker compose up -d postgres
cd src
python main.py
```

Сервер запустится на http://127.0.0.1:5000. Страница создания игры открывается по адресу `/`.

Посмотреть таблицы в контейнере:

```bash
docker compose exec postgres psql -U postgres -d sa -c "\dt"
```

## API

Обозначения на поле: 0 — пустая клетка, 1 — ходы игрока (всегда ходит первым), 2 — ходы компьютера.

### POST /game

Создаёт новую игру с пустым полем и сохраняет её в БД.

```json
{
  "id": "c3f9e555-b096-4e56-b4d0-2f8abd08898a",
  "cells": [[0, 0, 0], [0, 0, 0], [0, 0, 0]]
}
```

### POST /game/{id}

Принимает полное текущее поле с ходом игрока и возвращает поле с ответным ходом компьютера.

Запрос:

```json
{
  "cells": [
    [1, 0, 0],
    [0, 0, 0],
    [0, 0, 0]
  ]
}
```

Ответ:

```json
{
  "id": "c3f9e555-b096-4e56-b4d0-2f8abd08898a",
  "cells": [
    [1, 0, 0],
    [0, 2, 0],
    [0, 0, 0]
  ]
}
```

Если игра закончилась, в ответ добавляются поля `game_over` и `winner` (1 — выиграл игрок, 2 — компьютер, 0 — ничья).

Ошибки:
- `400 Bad Request` (`The board is not validated`), если изменена занятая клетка, изменено не ровно одна клетка или сделан ход не тем символом;
- `404 Not Found`, если игры с таким id нет.

### GET /game/{id}/state

Возвращает текущее поле игры, а при завершении партии ещё `game_over` и `winner`.

### GET /game/{id} и GET /

Отдают HTML-страницы: игровое поле и страницу создания игры.

### Пример игры через curl

```bash
# 1. создать игру
curl -X POST http://127.0.0.1:5000/game

# 2. сделать ход (подставьте полученный id)
curl -X POST http://127.0.0.1:5000/game/<id> \
  -H "Content-Type: application/json" \
  -d '{"cells": [[1,0,0],[0,0,0],[0,0,0]]}'
```

## Алгоритм Минимакс

Компьютер перебирает возможные продолжения игры и выбирает ход, который максимизирует его результат при условии, что соперник играет оптимально. Победа оценивается в `100 - depth`, поражение в `-100 + depth`, ничья в 0. Для поля 3×3 полного перебора достаточно, оптимизации не требуются.

## Ограничения

- Используется встроенный сервер разработки Flask, для продакшена нужен WSGI-сервер.
- Схема БД создаётся через `create_all`, он не изменяет уже существующие таблицы. При изменении моделей таблицы приходится пересоздавать (в будущем для этого подойдёт Alembic).
