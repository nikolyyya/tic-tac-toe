# Tic-Tac-Toe API

Веб-сервис для игры в крестики-нолики против компьютера. Компьютер выбирает ходы с помощью алгоритма **Минимакс**, поэтому проиграть ему нельзя: в лучшем случае получится ничья.

Учебный проект на Python. Цель: потренировать многослойную архитектуру и внедрение зависимостей на небольшом, но законченном приложении.

## Возможности

- Игра с компьютером через REST API
- Алгоритм Минимакс для выбора хода (с учётом глубины: компьютер предпочитает быстрые победы)
- Валидация поля: нельзя изменить уже сделанные ходы, нельзя сделать больше одного хода, нельзя пойти не тем символом
- Определение конца игры (победа, ничья) и победителя
- Несколько игр одновременно, у каждой свой UUID
- Потокобезопасное хранилище игр

## Стек

Python 3 · Flask · UUID · `threading.Lock`

## Архитектура

Приложение разделено на четыре слоя, у каждого своя ответственность:

```
src/
├── web/          # маршруты Flask, модели запросов/ответов, мапперы
├── domain/       # модели игры и интерфейс сервиса
├── datasource/   # хранилище, репозиторий, мапперы, реализация сервиса с Минимаксом
├── di/           # контейнер зависимостей
└── main.py       # точка входа
```

- **domain** ничего не знает о Flask и способе хранения данных.
- **datasource** хранит игры в `dict`, защищённом `Lock`; репозиторий скрывает детали хранилища и конвертирует модели через мапперы.
- **web** преобразует данные между форматом клиента (JSON) и внутренними моделями.
- **di** (класс `Container`) собирает граф зависимостей: хранилище (singleton), репозиторий и сервис.

## Как запустить

```bash
git clone https://github.com/nikolyyya/tic-tac-toe
cd tic-tac-toe
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install flask
python src/main.py
```

Сервер запустится на `http://127.0.0.1:5000`.

## API

Обозначения на поле: `0` — пустая клетка, `1` — ходы игрока (всегда ходит первым), `2` — ходы компьютера.

### `POST /game`

Создаёт новую игру с пустым полем.

Ответ:

```json
{
  "id": "c3f9e555-b096-4e56-b4d0-2f8abd08898a",
  "cells": [[0, 0, 0], [0, 0, 0], [0, 0, 0]]
}
```

### `POST /game/{id}`

Принимает **полное** текущее поле с ходом игрока и возвращает поле с ответным ходом компьютера.

Запрос:

```json
{
  "cells": [
    [1, 0, 0],
    [0, 0, 0],
    [0, 0, 0]
  ]
}
```

Ответ:

```json
{
  "id": "c3f9e555-b096-4e56-b4d0-2f8abd08898a",
  "cells": [
    [1, 0, 0],
    [0, 2, 0],
    [0, 0, 0]
  ]
}
```

Если игра закончилась, в ответ добавляются поля `game_over` и `winner` (`1` — выиграл игрок, `2` — компьютер, `0` — ничья):

```json
{
  "id": "c3f9e555-b096-4e56-b4d0-2f8abd08898a",
  "cells": [[1, 2, 1], [2, 2, 1], [1, 1, 2]],
  "game_over": true,
  "winner": 0
}
```

Если поле некорректно, сервис возвращает `400 Bad Request` с описанием ошибки (`The board is not validated`). Поле считается некорректным, если:

- изменена уже занятая клетка;
- изменено не ровно одна клетка;
- сделан ход не тем символом (первый ход всегда `1`, дальше ходы чередуются).

### Пример игры через curl

```bash
# 1. создать игру
curl -X POST http://127.0.0.1:5000/game

# 2. сделать ход (подставьте полученный id)
curl -X POST http://127.0.0.1:5000/game/<id> \
  -H "Content-Type: application/json" \
  -d '{"cells": [[1,0,0],[0,0,0],[0,0,0]]}'
```

## Алгоритм Минимакс

Компьютер перебирает возможные продолжения игры и выбирает ход, который максимизирует его результат при условии, что соперник играет оптимально. Победа оценивается в `100 - depth`, поражение в `-100 + depth`, ничья в `0`. Для поля 3×3 полного перебора достаточно, оптимизации не требуются.

## Ограничения

- Игры хранятся в памяти, поэтому после перезапуска сервера все партии пропадают.
- Используется встроенный сервер разработки Flask, для продакшена нужен WSGI-сервер.
